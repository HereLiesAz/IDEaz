## Production Readiness
- Close all P0 release blockers in the UX user-flow audit before production release.
- Execute and retain the device, accessibility, failure-injection, privacy, and store-policy evidence required by the audit.
- Completed the first P0 mitigation: PWA is the sole selectable production target; other repository types remain detectable but creation, initialization, and unfinished App View mounting are release-gated until their loops are complete.
- Corrected dependency submission to inventory only release-runtime configurations, preventing CI-only Gradle/AGP/test/lint dependency instances from being conflated with the shipped graph while retaining the pinned runtime Jackson and Bouncy Castle dependencies.
- Added bounded on-device tool use: local models can now read, list, write, and patch project files through the same sandbox as cloud providers, with strict round limits and plain-text fallback.
- Fixed `dependency-submission.yml` (a broken job-level `hashFiles()` condition made every run get silently *skipped* before submitting a graph — reported green, not failed, which is part of why it went unnoticed — so Dependabot alerts never auto-dismissed even where a patched version was already pinned) and bumped the Netty/Jackson pins that were genuinely stale.
- Root-caused and fixed the `build-and-release.yml` `Build with Gradle` hang (previously mitigated only with `timeout --kill-after=1m 30m` + live `tee` streaming + a JVM thread-dump watchdog, since neither the Netty/Jackson version bump nor Gradle's Enhanced Caching provider turned out to be the cause). A `jcmd Thread.print` captured mid-hang showed `:app:testDebugUnitTest`'s executor thread permanently blocked in `AsyncDispatch.stop() -> waitForAllMessages()` during Gradle's own test-executor teardown — every task after it in the graph (including the entire `:webruntime` module) completed normally in parallel, but the whole build can't finish until every task action's thread returns, including this stuck one. Root cause: `AIDelegateTest.kt`'s `@Before setUp()` and `pullRequestEventForwardsUrlToCallback()` each built a real `CoroutineScope(Dispatchers.Unconfined)` and wired it into a real `AIDelegate` (Robolectric, not `@Ignore`'d, runs every build) without ever cancelling it — unlike the sibling `SystemEventDelegateTest.kt`, which calls `cleanup()` on the same delegate constellation but is itself `@Ignore`'d. Since `app/build.gradle.kts` sets no `forkEvery`, the whole module's unit tests run in one forked JVM, so this single leaked scope was enough to hang the entire task's shutdown. Fixed by capturing the scope as a field and cancelling it in `@After`. `SystemEventDelegateTest` and `CrashReportingServiceTest` remain `@Ignore`'d with a "Crashes Robolectric runner in CI environment" note from a prior incident — worth re-investigating in isolation now that this shape of bug is understood. `OverlayDelegateWebContextTest`'s 3 flaky failures are unrelated (plain Mockito, no Robolectric, no owned threads) — likely `runTest`/`TestScope` timing sensitivity around its `delay(250)` path, not a teardown hang; still needs its own investigation.
- Disabled every `antigravity-*` automation job (including the two `vars.DEBUG`-gated `debugger` jobs, which held `contents: write` with no fork/author-association check of their own and weren't covered by the first pass) and `pr-contribution-guidelines-review.yml`'s `validate-pr` (each gated with `if: false`, not deleted): the `GEMINI_API_KEY` secret holds a value Google's API rejects outright. Re-enable by deleting the `if: false` guard once a valid key is set under Settings → Secrets and variables → Actions.
- Fixed `build-and-release.yml`'s concurrency/duplicate-build issue at the root instead of chasing key-matching bugs: it originally triggered on push to every branch plus every `pull_request` event, so a push to an open PR branch always fired two independent builds no matter how the concurrency group was keyed (two attempts at fixing the group's key both still left edge cases — see prior revisions of this file for that history). Now triggers only on push to `master` (a PR merge is itself a push to `master`) plus manual `workflow_dispatch`, with a single fixed concurrency group.
- Discovered and disabled `antigravity-dispatch.yml` (previously untouched by the antigravity-workflow cleanup): it triggers on every `pull_request` event including routine `synchronize` (any push to an open PR), and its dispatch logic only recognizes explicit `@antigravity-cli` commands or PR-opened/issue-opened events — anything else, including a normal push to your own PR, fell through to a job that unconditionally posted a false "I'm sorry, unable to process your request" PR comment, even though nothing was requested and no AI call was attempted. Also blocked on the same invalid `GEMINI_API_KEY` for its real functionality. Disabled with the same reversible `if: false` pattern as the other antigravity workflows.
- Ran five adversarial audits over the deployment pipeline, the AI-delegate architecture, the on-device model subsystem, app security, and documented UX claims. Fixed the deployment-pipeline findings: added `pr-check.yml` (compile + unit test + lint on every PR) to close the pre-merge gate gap the trigger fix above opened; switched `build-and-release.yml`'s concurrency to queue instead of cancel, since a cancelled run can force-push the release tag and then never upload the matching asset; fixed the JVM thread-dump watchdog leaking an orphaned `sleep` that could hold the job's stdout pipe open after being "killed"; deduplicated failed-build issue filing (was creating a fresh issue on every failed push); let `workflow_dispatch` actually publish a release instead of building and silently stopping; fixed `summary.yml`'s AI-inference step, which set the issue title/body as step env vars that the action never reads, so every new-issue summary was hallucinated from an empty prompt; fixed `jekyll-gh-pages.yml`'s `cancel-in-progress: true`, which contradicted its own adjacent comment; pinned `r0adkll/upload-google-play` (holds Play Store publishing credentials) to a commit SHA, the one unpinned third-party action in the pipeline; and scoped `dependency-submission.yml` to the default branch only, since non-default branches can't auto-dismiss alerts anyway. `pr-check.yml`'s very first run reproduced the exact `testDebugUnitTest` teardown hang above, at `:app:lintDebug` this time, but that job originally skipped the watchdog on the theory it just needed to fail loudly — it hung for 20 minutes with zero diagnostic output instead. Added the same watchdog there; a fresh AIDelegateTest-shaped leak search (every `CoroutineScope(` construction in `app/src/test`) turned up nothing beyond the already-fixed/already-ignored two, so the next hang, if it recurs, needs its own thread dump before guessing further.
- Fixed the AI-delegate architecture audit findings: `MainViewModel` is constructed directly in `MainApplication.onCreate` rather than through a `ViewModelStore`, so the framework's `onCleared()` (which unregisters `SystemEventDelegate`'s broadcast receivers, stops the file observer, and unbinds the build service) was permanently unreachable dead code — removed the unused `MainViewModelFactory.kt` that implied a different, never-adopted lifecycle, added a public `releaseResources()` entry point, and wired it into `MainApplication.onTerminate()` (best-effort only; real devices never call it, so this mainly makes the path reachable/testable rather than changing production behavior — the ViewModel's actual resources still live for the process lifetime by design). Fixed `JulesAdapter`'s session-resume seeding: a failed initial activity fetch used to be swallowed by `getOrDefault(emptyList())` (including `CancellationException`), leaving the dedup set empty so the next poll would treat the session's entire prior history as new and re-emit/re-apply every past patch — now retries a few times and propagates failure instead of silently proceeding empty. Also bumped the poll ceiling from ~45s to ~10 minutes: real agentic coding tasks routinely take longer than 45s, and a task that finished just after the old window closed was never observed as anything but timed out. Fixed `StateDelegate.clearLog()`: a batch already dequeued into the log-processing loop's local buffer (mid its 100ms debounce delay) would still get applied after a clear, silently repopulating the log the user just emptied — added a generation counter so any batch tagged with a superseded generation is dropped at processing time regardless of when it was dequeued, with a regression test that reproduces the exact race via controlled virtual time. Fixed `AIDelegate.startContextualAITask` firing two overlay prompts in quick succession: the second call overwrote `contextualTaskJob` without cancelling the first, so both ran concurrently and whichever `finally` block happened to run last decided the loading-spinner state — now cancels the previous job first, and each job's `finally` only touches state if it's still the current job (a superseded job's `finally` still runs on cancellation, but is now a no-op for that state). Fixed a `catch (e: Exception)` in `fetchSessionsForRepo` that swallowed `CancellationException` too, contradicting the explicit rethrow pattern already documented and followed elsewhere in the same file. And fixed the exact leaked-`CoroutineScope`-in-a-test shape (see `AIDelegateTest` above) latent in `SystemEventDelegateTest`, currently `@Ignore`'d but would reintroduce the hang the moment someone re-enables it without noticing.
- Fixed the security & secrets audit findings: only the Jules and Google API keys were ever routed through `AndroidKeystoreCredentialStore` — the GitHub PAT, five other provider API keys, and both signing passwords sat in plaintext `SharedPreferences` (backed up off-device by Android's Auto Backup); `SettingsViewModel.SECURE_CREDENTIAL_KEYS` now covers all ten, with a `readSecureOrLegacyCredential()` helper so `BuildService` and `CrashHandler` (which read these values outside `SettingsViewModel`) transparently pick up a value from either the Keystore-backed store or an existing plaintext install without a migration step. Excluded the imported release-signing keystore file (`user_release.keystore`) from Auto Backup — it was the one credential-shaped file on disk with no backup rule of its own. Closed an arbitrary-file-write in `SettingsViewModel.importSettings`: the imported keystore's destination path wasn't canonicalized/contained before writing, the same Zip-Slip shape already fixed elsewhere in `BackupManager`/`RemoteBuildManager`. Extended `LogSanitizer` to redact GitHub fine-grained PATs and OpenAI/Anthropic/HuggingFace/Groq key formats, previously only covering a couple of provider shapes, with a new `LogSanitizerTest` covering each. Gated both OkHttp clients' (`JulesApiClient`, `GithubApiClient`) `HttpLoggingInterceptor` to `Level.BODY` only in debug builds — release builds were logging full request/response bodies, including auth headers, to logcat unconditionally. Fixed `GithubIssueReporter` sanitizing only the issue body and not the title before posting to the public repo, so a secret at the start of an exception message or build-log first line went out in plain text. Scoped both `IdeazOverlayService` and `IdeazAccessibilityService`'s dynamic broadcast receivers to `ContextCompat.RECEIVER_NOT_EXPORTED` (both were world-exported below API 33 — any app on-device could drive the accessibility inspector or overlay interception). Fixed a case-mismatched literal `"GOOGLE_API_KEY"` lookup in `RepoDelegate` (the real key is `KEY_GOOGLE_API_KEY = "google_api_key"`) that silently meant the Google API key was never included in remote build uploads. Removed the dead, zero-caller `ApiClient.kt`. And scoped `WebProjectHost`'s two privileged `Ideaz`/`IdeazBridge` JS interfaces so they're only added when the WebView is actually loading this app's own asset-loader origin — they were previously added unconditionally at WebView construction, meaning the passthrough remote-URL load path (`projectDir == null`) handed the same native bridge to arbitrary external pages.
- Fixed the on-device model audit findings. `MediaPipeRuntime` was passing `maxOutputTokens` (256/512/768) into `LlmInferenceOptions.setMaxTokens`, which is MediaPipe's *total* prompt+output budget — every real prompt exceeded it before generation could even start, so on-device MediaPipe models failed on essentially every turn; fixed to pass `maxContextTokens`, and reworked `localInferenceLimits()` so `maxPromptChars` now reserves `maxOutputTokens` of headroom inside `maxContextTokens` instead of consuming the whole budget itself (both are shares of one total window, not independent limits) — this also brings llama.cpp's self-sizing native context (`n_ctx = n_prompt + maxTokens + 8`) into the same bound for free, since its input is drawn from the same char-bounded prompt. AICore has no context-budget API at all; documented why prompt-side bounding is the only lever available there. That leaves context bounding meaningfully enforced on 3 of 4 backends (was 1: ONNX only) with the 4th (AICore) explained rather than silently ignored. Wrapped `LocalModelDownloadWorker`'s initial `setForeground()` call in a try/catch: API 31+ throws `ForegroundServiceStartNotAllowedException` when a WorkManager backoff retry fires while the app is backgrounded, which previously escaped `doWork` uncaught and left the UI showing an unexplained failed download; it now retries (or fails with an explanatory message once retries are exhausted). Investigated the "failed Keystore migration leaves plaintext silently" finding and found it's already covered by `` `failed secure migration retains legacy Hugging Face token` `` in `SettingsViewModelTest` — the behavior (retain + log + retry next call) is intentional and tested, not a gap. For the catalog-integrity finding: fetched real size + SHA-256 for 4 of 6 downloadable catalog entries directly from the Hugging Face Hub tree API (LFS object metadata, not by downloading multi-GB files) and populated `expectedSizeBytes`/`sha256` on the Qwen2.5 0.5B, Gemma 3 Nano E2B/E4B, and Phi-3.5 ONNX entries — the verification gate in `ModelDownloadManager` now actually runs on those. That lookup also surfaced two catalog entries with broken upstream URLs, previously undetected: `unsloth/gemma-2-2b-it-GGUF` now 401s at the Hub API entirely (repo likely renamed/moved/private), and `google/gemma-2-2b-it` — the source for the MediaPipe `.task` entry — ships raw `.safetensors` weights with no `.task` file at all, so that URL 404s outright. The Phi-3.5 ONNX entry's own URL was similarly dead (`cpu-int4-rtn-block-32-acc-level-4/` no longer exists upstream) and has been repointed to the current `cpu-int4-awq-block-128-acc-level-4/` variant with freshly verified per-file size/hash. Left the two still-broken entries unresolved rather than guessing replacement URLs — locating a model's correct current home and checking its license/redistribution terms is exactly the "manual verification" #37/#38 below already call for, not something to do blind.
- Fixed the UX & user-flow audit findings. The PWA-only release gate (`ProjectType.selectable`) had two unguarded side doors alongside its correctly-enforced front door (`MainViewModel.loadProject`): importing an external folder via SAF (`registerExternalProject`) called `saveAndInitialize` with no gate check at all, and cloning an existing repo (`RepoDelegate.selectRepositoryForSetup`) never even re-detected project type after cloning, so a cloned Android or plain-web repo silently ran under whatever type was previously open. Both now detect and gate exactly like `loadProject` does, refusing (and, for the import path, deleting) anything outside `selectable`. Added `ProjectAnalyzerTest` cases that drive the real detector against `ProjectType.selectable` on synthetic project layouts, since the only existing test (`ProjectTypeTemplateTest`) checked the `selectable` declaration against a literal list and would pass even if every enforcement site were deleted. Fixed `FileContentScreen` opening any file with no type check and reading/writing it with lossy `readText()`/`writeText()` — a PWA's manifest-required icon PNGs were one tap-open-tap-save away from being overwritten with replacement-character bytes, and a deleted/unreadable file threw uncaught. It now probes for a NUL byte (the same heuristic `git` uses) before ever decoding as text, refusing to open binaries with an explanation instead of corrupting them, and handles missing/unreadable files as a message instead of a crash. Fixed `MainViewModel.launchTargetApp` unconditionally entering App View for web-like projects even when `index.html` was missing — `currentWebUrl` stayed null, and `MainScreen`'s App View layer treated null URL as "must be an Android project, Phase 2 placeholder" regardless of actual project type, so a PWA missing its entry file showed "Android target host arrives in Phase 2." Now it surfaces the real problem and stays on the current screen instead. Fixed `AiChatTab` hardcoding "Gemini" as the model-turn label regardless of which provider actually replied (including on-device models) — it now reads the same `KEY_AI_ASSIGNMENT_DEFAULT` assignment `sendChatMessage` itself routes through. And gave `RepoDelegate.fetchGitHubRepos` a real error state (`repoFetchError`): a failed fetch previously only logged to the overlay console and left the repo list empty, so `ProjectCloneTab` rendered "No repositories found." identically for an offline user with a valid token and an account that genuinely has none, with no retry beyond the generic refresh icon — it now shows the actual error with a dedicated Retry button.
- Root-caused a second, unrelated shape of the `testDebugUnitTest` teardown hang — this one hit `build-and-release.yml` three times in one day (05:13, 06:56, 10:14 UTC), each timing out at the outer 30-minute limit. Unlike the earlier `AIDelegateTest` leaked-scope hang, the JVM thread dumps this time showed no leaked `com.hereliesaz` code anywhere in the *daemon's* stuck thread (pure `AsyncDispatch.stop()`/`waitForAllMessages()` Gradle-internal frames) — but a second, still-live worker JVM dump from one of the three runs caught the real culprit directly: a thread parked in `kotlinx.coroutines.BlockingCoroutine.joinBlocking` inside `GithubIssueReporterTest.kt`'s `` `test reportError with stackTraceOverride` ``. That test calls `reportError(token = null, ...)`, which falls through to `withContext(Dispatchers.Main) { context.startActivity(intent) }` - and this project has no `robolectric.properties` or `@LooperMode` annotation anywhere, so Robolectric defaults to `PAUSED` looper mode. A plain (non-`.immediate`) `Dispatchers.Main` post under `PAUSED` just queues on the main `Looper` and nothing in the test ever idles it, so the post never runs, `withContext` never resumes, and the surrounding `runBlocking` deadlocks forever. Since `app/build.gradle.kts` sets no `forkEvery`, that one permanently-deadlocked test hangs the whole `testDebugUnitTest` task - and therefore the whole build - deterministically, every time it runs (the run where the dumped worker PID had already exited was simply a different worker than the one running this test class; Gradle test workers execute test classes across multiple parallel forked JVMs). Fixed by adding `@LooperMode(LooperMode.Mode.LEGACY)` to the test class, which executes posted Handler work synchronously instead of queuing it - correct here since the test only checks dedup/sanitization logic, not real Looper timing. Swept every other `Dispatchers.Main` production call site (`GeminiAppBridgeAdapter`, `RepoDelegate`, `MainViewModel`, `SettingsViewModel`) against the Robolectric tests that construct their owning classes; none of the others are reached from a `runBlocking`/`runTest` body the way this one was, so none share the same deadlock shape.
- Once the deadlock fix above stopped `pr-check.yml` from hanging for 30 minutes with zero output, it surfaced a real `lintDebug` regression from this session's earlier `WebProjectHost.kt` edit (see the security & secrets bullet above): `webView.addJavascriptInterface(ideazJsInterface, "Ideaz")`/`"IdeazBridge"` started failing lint's `JavascriptInterface` check with "None of the methods in the added interface (T) have been annotated" - the literal `(T)` is lint's UAST resolver failing to infer the concrete type through `remember { IdeazJsInterface(context) }`'s generic `remember<T>` signature. Explicit type annotations on both `remember` calls (`val ideazJsInterface: IdeazJsInterface = remember { ... }`) did *not* fix it - confirmed by a second CI run with the identical error - so they were left in place (harmless, clearer code) and the check is suppressed directly with `@Suppress("JavascriptInterface")` on `WebProjectHost` instead: both `IdeazJsInterface.onInspectResult` and `WebViewBridge.onElementTapped` are genuinely `@JavascriptInterface`-annotated, so this is a confirmed lint false positive, not a real gap.
- The first fix attempt for the `GithubIssueReporterTest` deadlock above, `@LooperMode(LooperMode.Mode.LEGACY)`, made the hang symptom disappear (the build finished in 3 minutes instead of timing out at 30) but replaced it with a new, equally deterministic failure: `Process 'Gradle Test Executor 1' finished with non-zero exit value 1`, reproduced identically on two separate CI runs, within ~1.5-2.5 seconds of the task starting - too fast for any real test to have run. `LooperMode.Mode.LEGACY` was not used anywhere else in this test suite; Robolectric builds a separate, per-mode sandboxed classloader the first time a given `LooperMode` is used, and that appears to be incompatible with this project's Robolectric 4.16.1 / Java 21 combination on this CI image. Replaced with the standard, lower-risk fix already established elsewhere in this codebase (`StateDelegateTest`): `Dispatchers.setMain(StandardTestDispatcher(testScheduler))` inside `runTest`, using the *same* scheduler `runTest`'s own `TestScope` receiver runs on (not a bare `StandardTestDispatcher()`, which would just recreate the "queued forever" problem via an unrelated, never-advanced scheduler of its own) - this routes the `withContext(Dispatchers.Main)` call through kotlinx-coroutines-test's cooperative scheduler instead of the real Android `Looper`, sidestepping the Robolectric pausing question entirely without touching `LooperMode` at all.

## On-device Model Production Coverage

The on-device provider is not production-complete until every unchecked item below has device evidence. A model producing one charming sentence on the maintainer's phone is a demo, not a subsystem.

- [x] Provide a unified runtime registry with hardware/backend availability filtering.
- [x] Provide download, HTTP-range resume, progress, selection, and deletion controls.
- [x] Connect the selected local model to `ConversationalAiClient` assignments.
- [x] Add bounded `read_file`, `write_file`, `list_files`, and `apply_patch` tool use with malformed-output fallback.
- [x] Implement staged exact-size/SHA-256 verification, corrupt-payload deletion, atomic activation, and manifest-bound verification markers.
- [ ] Reduce the production catalog to models whose URL, immutable revision, exact files, license, and redistribution terms have been manually verified. 2 of 6 downloadable entries (`gemma2-2b-it-q4-gguf`, `gemma2-2b-it-mediapipe`) are currently known-broken (dead upstream URLs, discovered while populating checksums below) and need a human to find their correct current source.
- [ ] Populate and require an exact byte count and SHA-256 for every downloadable production catalog file. 4 of 6 done (`qwen2_5-0_5b-instruct-q4-gguf`, `gemma-3n-e2b-it-q4-gguf`, `gemma-3n-e4b-it-q4-gguf`, `phi3_5-mini-onnx`), sourced from the Hugging Face Hub tree API's LFS object metadata rather than downloading each file. The remaining 2 are blocked on the URL problem above.
- [x] Preflight available storage, including existing partial/final bytes, download staging space, and a 256 MiB safety reserve, before network work begins.
- [x] Move downloads to unique WorkManager jobs with connected-network constraints, foreground notification progress, cancellation, bounded retry/backoff, and process-death restoration.
- [x] Persist download state and reconcile interrupted `.part` files, server range behavior, catalog changes, and user deletion.
- [x] Move gated-provider tokens from plain preferences into the Android Keystore credential path; exclude them from backup/logs and include plaintext only inside explicitly requested password-encrypted exports.
- [x] Cache inference engines safely, serialize access per backend, unload on memory pressure/model change, and bound prompt/context/output tokens per device tier.
- [x] Replace assistant-text `Error:` responses with structured local-provider failures carrying retry and consent-based fallback policy plus bounded, content-free diagnostics.
- [x] Add one-shot cloud fallback gated by the current diagnostic, failure safety policy, configured Gemini credential, and an explicit disclosure/approval button; never transmit silently.
- [x] Let the local chat model request one read-only Gemini consultation before any other tool, with an exact payload preview, per-call consent, stale-request binding, no cloud IDE tools, and no retransmission when local resume is retried.
- [x] Validate tool edits before reload, create an undo checkpoint, and surface changed files for user approval.
- [x] Add unit coverage for integrity, resume semantics, storage rejection, cancellation, catalog migration, tool-loop limits, and structured failures.
- [ ] Add physical-device tests across the supported ARM64/RAM matrix for cold start, tokens/second, peak RSS, thermal throttling, backgrounding, process death, and repeated inference.
- [ ] Publish the supported-device/model matrix and experimental limitations in Settings and release documentation.
- [ ] Complete privacy, model-license, and telemetry review; never collect prompts, source, model inputs, or generated output by default.
